# 验证范围与限制

本报告只针对这个通用仓库。所有用例使用虚构资料、临时生成文件和模拟视觉模型；没有使用原项目的真实培训资料、用户截图或答案记录。

## 已执行

- Windows Python 3.12：36 项测试，35 项通过，1 项可选文档/视频测试因对应模块未安装而跳过。
- 真实本地 HTTP 链路、模拟视觉 API：提交 6 张虚构题图，完成识别、检索、作答、复核、状态读取及 Markdown 导出。
- 并发测试：题目同时运行、空位连续补题、后续截图识别与前面题目处理重叠、单题错误隔离、请求信号量释放。
- 资料与检索测试：中文分词、原文窗口完整性、提取缓存、删除来源后的新清单、资料范围筛选、索引与模型版本不匹配拒绝加载。
- 多模态线路测试：模拟 embedding 编码器验证图片走 image 输入、文字走 text 输入，缓存复用；这不是 WeMM 效果评测。
- Web 安全边界测试：Host 校验、缺少令牌的 POST 拒绝、未索引私有文件不可读取、源文本 HTML 转义。
- CLI 虚构示例：导入、构建关键词索引、启动检索页面，浏览器已验证示例内容。
- 答题页面 JavaScript 语法检查。

Linux 独立虚拟环境（Python 3.12.15）实测：36 项测试全部通过，无跳过。额外验证了自动生成的 PDF 页面渲染/文字提取、DOCX 文字提取、MP4 抽帧去重、视频字节范围响应和时间点回看。CLI 完成虚构资料导入、关键词建索引和检索；构建了可安装的 wheel。

该环境的主要依赖：NumPy 2.5.4、Pillow 12.3.0、OpenCV Headless 5.0.0.93、PyMuPDF 1.28.2、python-docx 1.2.0。没有为本轮验证安装或修改 GPU 驱动、生产模型服务、OCR/ASR 权重或真实业务库。

## 本轮不宣称已验收的内容

- 新仓库在任意 AMD/NVIDIA 型号上的驱动安装和 WeMM 显存峰值。
- 所有可能的视觉 API 供应商兼容性与真实作答准确率。
- 真实 OCR/ASR 模型下载、识别准确率、所有文档布局和视频编码。
- 公网多用户部署、任务跨进程恢复或生产负载能力。

WeMM 编码器基于官方接口和此前实现抽象出来，但本轮没有为验证新仓库而停止已有 GPU 服务或额外加载占显存的模型。部署者应按安装教程先做显卡自检，再用少量非敏感资料验证向量检索与真实视觉 API。

## 重要限制

- 固定间隔采样可能漏掉短暂停留的页面；视频中的连续运动可能产生重复画面。
- DOCX 只提取段落和表格，PPTX 依赖 LibreOffice 转换效果，OCR/ASR 可能误识别数字与否定词。
- 关键词或向量检索得到的相关材料未必足以证明某个答案，模型二次复核也可能重复同一错误。
- 一个活动批次、单用户、本机 loopback 服务；网页进程重启会中断未完成题。
- 向量用 NumPy 精确扫描，适合个人规模；大量图文应评估内存、检索延迟及 ANN 改造。
- 模型配置的 revision 由部署者与实际本地快照对应；不要原地替换权重后继续复用旧缓存。
- 依赖范围不是完整平台锁文件，不保证未来任意传递依赖组合可用；部署后应保存已验收环境版本。
