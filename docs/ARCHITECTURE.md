# 架构与实现

## 目标和边界

输入是用户有权使用的本地视频与文档，以及待练习的选择题截图。输出是可查阅的原文知识库、相关页面/画面、答案建议、逐项判断与可核对引用。目标是降低查资料成本并保留证据，而非承诺考试成绩。

通用仓库重新实现了配置、资料导入、索引、阅读器和 HTTP 服务，复用了已有批量答题工作流的通用代码与虚构单元测试。没有复制业务语料、真实题库、生产索引、缓存、密钥或旧机器配置。它不依赖旧目录结构中的其他项目文件。

## 导入与证据

`ingest` 扫描一个输入目录，逐文件计算 SHA-256，用“相对文件名 + 内容哈希”标识来源。提取结果以“内容 + 导入配置”命名缓存。旧缓存不自动删除；导入成功后原子发布新的 `corpus.json`。源目录删去的文件不会进入新一代清单，但物理缓存仍保留，需由管理员按数据保留策略清理。

| 类型 | 处理 | 证据定位 |
|---|---|---|
| Markdown / TXT | UTF-8 原文按连续窗口切片 | 文件名、记录锚点 |
| DOCX | 段落、表格文字 | 文件名、记录锚点 |
| PDF | 每页渲染 + 文字提取，可选 OCR | 页码、页面 PNG |
| PPTX | LibreOffice 转 PDF 后按页导入 | 原 PPTX 文件名、页码 |
| 图片 | 转为 PNG，可选 OCR | 原文件名、PNG |
| 视频 | 固定间隔采样、ROI 变化比较，可选 OCR/ASR | 时间点、完整画面、转写起止时间 |

文字按 1,400 字符窗口切片，相邻重叠 160 字符。不会将模型重写后的总结当作原始证据。`knowledge.md` 是带来源标题的原文汇编；OCR、ASR 与复杂文档解析仍可能出错。

## 索引与检索

三种互斥配置：

1. `none`：SQLite FTS5。中文使用连续双字词，英文和数字按词切分。
2. `text`：文字/图像 OCR 文字向量 + FTS；不编码图像像素。
3. `wemm`：原图向量和文字向量分别写入同一模型版本的索引，再与 FTS 融合。

向量都转为 float32 并 L2 归一化，点积即余弦相似度。小型个人库使用 NumPy 精确扫描，避免引入必须运行的向量数据库。融合用 RRF：每个检索排名贡献 `1 / (60 + rank)`，不直接相加不可比的 FTS 与向量分数。

向量缓存由完整模型配置和输入内容哈希分区。每次构建创建独立 generation，全部组件写完后更新 `index/current.json`。服务启动校验语料指纹和 embedding 配置是否匹配，拒绝加载过期/不同模型索引。服务运行期间保持这一代快照，更新后需重启。

WeMM 在进程内用互斥锁序列化 GPU 编码。题目队列并发不等于 GPU 同时执行多个大批次，避免高峰显存失控。索引构建逐条编码，优先稳定运行和复用缓存。大规模库可后续换 ANN 检索。

## 截图到答案

1. 浏览器接收剪贴板或文件，多图压缩后上传。
2. 视觉 API 按截图从上到下识别最多 5 道题，保留否定词、题型和选项，忽略已有勾选、水印和分值。
3. 提取后的题立即进入线程池，后续截图识别可以与前面题目的处理重叠。
4. 使用完整题干、所有选项和关键词检索图片、原文与语音片段。
5. 将证据在本题内重新编号：`P1…` 图片、`H1…` 文档段落、`T1…` 检索原文。该编号仅在本题有效。
6. 作答模型看到清理后的题干与课程证据，不看到题图中的预先勾选。随后同一模型执行第二轮证据和否定词复核。
7. 校验选项、单选约束、引用存在性、逐项判断一致性。不确定结论标为 `needs_review`。
8. 用户允许时，额外生成无充分资料依据的 `answer.inference`。它没有课程引用，不能升级为“资料已证实”。

二次复核来自同一个模型，不是独立人工审核；引用 ID 存在也不证明逻辑正确。检索不到不等于知识不存在，排名第一也不等于支持答案。

## 并发与持久化

每批最多 100 图、每图最多 5 题，单图解码后最多 4 MiB，合计 64 MiB。HTTP 请求体上限 96 MiB，覆盖 Base64 开销。当前只接收一个活动批次，批次内部默认 3 路、可设 1–8 路。

线程池完成一题就领取下一题，不等待一组题全部结束。每题内部保持“检索 → 作答 → 复核 → 可选推断”。本批模型请求共享相同并发预算，截图识别也计入预算，另有可配置的全局上限。单题异常只标记本题失败。

`job.json` 每次变更在重入锁内原子替换，避免多个线程覆盖状态。关闭浏览器不影响进程内任务；网页进程退出则中断。重启将遗留 `running` 标为 `interrupted`，不自动重复付费调用，需人工只重提未完成题。

## 数据目录

```text
data/
  corpus.json                         # 来源与证据完整清单，含本机源文件路径
  knowledge.md                        # 原文汇编
  cache/ingest/<fingerprint>.json      # 文件提取缓存
  cache/vectors/<model>/<hash>.npy     # 可复用向量
  outputs/deliverables/assets/...      # 只含页面/画面图片
  outputs/quiz/<job-id>/               # 用户题图、进度、答案和证据
  index/current.json                  # 已发布索引代号
  index/generations/<id>/
    snapshot.json                     # 索引对应的语料快照与模型配置
    lexical.sqlite
    vectors.npy
```

`outputs/deliverables` 是通用答题工作流的内部兼容路径，不关联任何具体组织。实际业务数据、绝对源路径和用户题图均在忽略的 `data/` 内，不应纳入公开仓库。

## 扩展点

- `ingest.extract`：增加 HTML、表格、图片型 DOCX 等解析器。
- `Embedder.encode`：接入独立多模态 embedding API，分离 GPU 服务。
- `Search.query/slides/text`：替换向量存储、增加 reranker、按段落命题的定向检索。
- `ConfiguredQuiz.config` 与 `QuizAPI.call_model`：增加视觉识别/推理不同模型，支持 Responses 适配器。
- `QuizAPI.run/process_item`：持久化队列、任务取消、幂等重试与跨进程工作器。

未来可增加人工标注的独立评测集，分别测量题目识别率、检索 Recall@k、严格回答覆盖率、回答准确率与推断准确率；不要将“全部处理结束”当作“全部答对”。
